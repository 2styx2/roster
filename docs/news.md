# What's new

What changed in each Release of roster, the CLI and the app together, newest first: what's new, what changed, what's gone and what's on its way out. The app says once, on its first start after an upgrade, "roster 0.2.0: what's new: `:help news`". [Deprecated names](deprecated.md) lists every old name that still works, and what replaces it.

Each Release has the same sections, left out when empty: **Breaking** (something you have to change), **New**, **Changed**, **Security**, **Fixed**, **Removed** and **Deprecated**. Inside a section the bullets are grouped by area: the CLI, the app, and the `roster serve` API with the API version that brought the change.

## Unreleased

### New

**CLI**

- **Several Inventories, one active** (#201): name the team's Inventory and your own with `roster inv add work ~/infra/roster.yml` and `roster inv add home ~/home-net/roster.yml`, switch with `roster inv use home`, and run one command against the other with `roster --inv work …`. Each one's `setup` and `sync` write its own ssh config, known_hosts and `ROSTER.md`, so syncing home never touches work's, and `ssh pi` works for a Host in any of them (the active one wins a name clash). `roster check --box`, `setup` and `sync` warn when the same machine (the same host key) is in two of them, or two use the same Host name or address. With no named Inventories nothing changes. `roster inv which` prints the file roster uses, and the app now asks roster for it, so the two always agree. serve API 27 adds `inventories.list` and `inventories.use`.

**App**

- **A collapsed cluster on a graph moves whole** (#237): `m` on it, then `h` `j` `k` `l` until Enter keeps the place (Esc puts it back), or drag it. Its nodes go with it and keep their places in it, so it opens looking as it did. It stays where you put it and is remembered as yours: a cluster you put it on moves to the nearest free place, and nothing else does. Before, `m` there said to open the cluster first. See [Graphs](plugins.md#graphs).

### Changed

**CLI**

- **roster.yml is checked by type as it loads** (decision Q113): a value of the wrong kind that roster used to trip over later now stops the load with roster's usual error, naming the key and never the value, e.g. `workers: lots` gives `error: roster.yml: workers: input should be a valid integer…` (code 1 in `roster serve` and `--json`) instead of a Python traceback. What loaded before still loads, except a `workers:` or `claude_inline_limit:` below 1 or with a fraction, and a `provider_dirs:` entry that isn't a path; `--json` and serve's results keep their shape (a Host's default `login` user written as a number now comes out as text, as its ssh user always did). roster now needs Pydantic 2 (installed with it). See [Development](development.md#languages-and-types).

**App**

- **A Host's row in the Sidebar has a menu instead of buttons** (#314): selecting a Host no longer shows ⓘ, ✓, ✎ and × on its row. Right-click it, or press the Menu key or Shift+F10 on it in App mode (`menu`), for Open, New Session, Details, Check, Edit, Rename, Move to another group, Add to a Folder, Remove from the Inventory and any Plugin's own actions on that row (a Folder's "Remove from Lab"), each running the same command its button or key did, with the keys shown beside it. It's a keyboard and screen-reader menu: arrows, Home/End, a letter, Enter, Esc (decision Q156). Groups, Folders and Sessions keep their buttons. See [The Sidebar](app/keyboard.md#the-sidebar).

### Fixed

**CLI**

- **`roster discover --write` and `roster mesh cut` sync this Box** after they change `roster.yml`, as the app's changes do: its ssh config and Claude files follow, so a Host they wrote needs no `roster sync` by hand. If the sync fails, the edit stays, and a `warning:` on stderr says why and to run `roster sync`; the command's exit status is the edit's. See [Commands](cli-reference.md#commands).

- **Quitting mid-Mesh run records what it didn't finish on a busy computer too:** closing `roster serve` (quitting the app) during a Mesh plan or apply gives the job a moment to note in `mesh.json` which Hosts are left; on a loaded or slow machine that moment was spent loading the SSH library, so serve could exit with nothing noted and `mesh.status` didn't say those Hosts were pending. The library now loads when the run starts.

**App**

- **sudo's prompt fill on Windows no longer refuses a repaint of the same screen** (#284): ConPTY repaints what it already drew while the vault answers, and drew blank cells in whatever colour its own buffer held, which roster took as a changed screen (`prompt fill refused before the probe: … changed the screen`). roster's screen now compares styles as a terminal shows them: a blank shows only its background, every form of the same SGR is the same style, and ConPTY's scrollback clear draws nothing; anything that shows differently still refuses before anything is typed. That refusal's log line now says what differed (the cursor, the size, which rows and whether characters or only styles, and any sequence roster's screen doesn't model), never the text. Wherever roster's screen can't follow the terminal exactly (a wide character, an emoji with a variation selector, a curses program's line-drawing charset, a mode it doesn't model), it no longer guesses: on every platform, the fill key refuses in that Session, before anything is looked up or typed, until `reset` in it, and the message line says so. See [Filling a password prompt](app/security.md#filling-a-password-prompt).
- **Copy and paste match Windows Terminal more closely** (#302): on Windows, copied lines end with CR LF, as Windows Terminal's do, roster's own rule now rather than xterm.js's (LF on Linux and macOS, as their terminals). On macOS, Option takes the mouse back from a program with mouse reporting on (Claude Code, vim with `mouse=a`, tmux), as Shift does elsewhere and Option does in iTerm2 and Terminal.app: Option+drag selects in the terminal and Option+right-click pastes; nothing did before. Option+drag there now selects lines instead of a block (decision Q155). See [Copy and paste](app/keyboard.md#copy-and-paste).
- **A huge count in a terminal sequence no longer freezes a tab** (#305): a Host (or a crafted file you `cat` there) printing `ESC[99999999L` ran the terminal out of memory, and `ESC[99999999M` held the whole app for over a minute. Every count is now capped at 9999 before the tab's terminal, the fill key's prompt check and the Plugins' `terminal_output` read it, more than any screen's rows or columns, so what's drawn is the same; OSC 52 and everything else in the output is untouched (decision Q153).
- **Shell hooks see fish's prompt:** the auto-send (`shell_hooks`) and `:integrate` never saw a real fish prompt (fish moves the cursor back over its prompt, and a detached HEAD's `((f5c479ed))` didn't fit), so nothing was sent in fish. roster now reads the prompt off the Session's screen as a terminal draws it, takes fish's git branch and failed status, and still sends nothing at a password prompt, however it's drawn: a prompt with a word asking for a password, passphrase, PIN, one-time code or token on its line or just above it is refused, in several languages. See [Shell hooks](plugins.md#shell-hooks-roster-sets-it-up).
- **A Plugin that fails to load in `:tutor`'s demo says so:** its notice names it "coach (in the demo): …", so it no longer reads like a failure in your workspace, where the same Plugin still runs. See [A Plugin's tutorial](plugins.md#a-plugins-tutorial).
- **Copying in Claude Code, vim and tmux works** (#293): a program that turns on mouse reporting draws its own selection and copies it with OSC 52, which roster now puts on the clipboard, as Windows Terminal does, so a plain drag in Claude Code copies. Write only, from the Session on screen, text up to 1 MiB; `roster.o.terminal.osc52 = false` turns it off (decision Q149). While such a program has mouse reporting on, a right-click with nothing selected is the program's and no longer pastes; Shift+drag and Shift+right-click are the terminal's own, as before. Copied lines drop the spaces a program padded them with, as in Windows Terminal. See [Copy and paste](app/keyboard.md#copy-and-paste).
- **A paste can't end a bracketed paste early any more** (security): text holding the end mark (`ESC [ 201 ~`) ended the paste and ran what followed as typed. Every paste (Ctrl+V, Ctrl+Shift+V, Shift+Insert, right-click) now drops control characters but tab and line ends, as Windows Terminal does. See [The clipboard](app/security.md#the-clipboard).
- With `auto_reload` on, an outside edit of `roster.yml` saved just as the app started watching it (at start, on a busy computer) is applied too: it could be taken for how the file already was and never applied until `:source`.
- A Plugin's request through `plugin_proxy` that's redirected to a name this computer is slow to look up now ends at the request's `timeout` ("no answer within N s") instead of waiting on the lookup, and holds up none of the Plugin's other requests. Every redirect is still checked the same way before it's followed. A user or password in a redirect's address is never sent, and on to another site only a Plugin's headers that carry no credential go along (`Accept`, `User-Agent`, …): a token in `X-Api-Key` or any other header stays with the site it was sent to. Each hop of a redirect counts in `:plugins` under its own site. See [The network](plugins.md#the-network).
- `:options` names the returned table's line for an option it sets over a `roster.o` line (after `:config import-terminal`, it named the import block's line), and an error in that value is reported there too.
- The editor types' `roster.config.OptionName` (what `roster.o.get` and `roster.o.reset` take) says so, and takes a map's own keys (`"views.files.width"`) as well as the names it lists. Run `:config types` again to update them.
- **The fill key works on Windows at sudo with `pwfeedback`:** Windows' ConPTY repaints parts of the screen it already drew, and the fill took that as the prompt printing something, so it refused there. Now, on Windows, output before roster's check counts only if it changed what the screen shows; a new prompt, `Sorry, try again.` or any other change still refuses, before anything is typed. **On Windows the fill key now fills only sudo's own prompt for the Session's Host:** ConPTY can hide an echo of roster's check, so at other prompts (`Password:`, ssh's login, a nested ssh's Host) roster can't tell the prompt doesn't echo, and it says so instead; type those yourself. Everywhere, roster's check now leaves its letter on the line for 800 ms before taking it back (a fill takes about 1.6 s), keys you type during a fill wait until it's done instead of landing in the middle of it, a resize during a fill refuses it, and output while the vault answers refuses before anything is typed, keeping the prompt offered. The log line (stderr) for a refused fill at sudo's prompt says which check refused it, still with no text but `*` and space. See [Filling a password prompt](app/security.md#filling-a-password-prompt).
- **On Windows the fill key is offered only where it can fill** (#304): at `Password:`, ssh's login or a nested ssh's Host's prompts the note now says roster fills only sudo's own prompt for the Session's Host there, with no Fill button, and `␣ p` says the same instead of trying (decision Q154).
- **A nested ssh's password goes only to that ssh** (security, #284): if the ssh had ended, or another command had started, by the time you pressed the fill key (the app a moment behind), the far Host's password could go to the same-looking prompt on the Session's own Host (its `sudo` for the same user). roster now fills a nested Host's prompt only while the Session's own shell, by its own marks, still runs that very ssh; otherwise it types nothing and says so (decision Q154). See [A nested ssh](app/security.md#a-nested-ssh).
- **A sync that failed after a pull is no longer silent:** when the pull a form (`:edit`, `:host add`, Save to vault) runs before saving brought new commits and this Box's ssh config didn't follow, the form's pull line says so, with `roster sync` to run; `:pull` says it too.
- **A sync that failed after a Mesh cut says so:** the mesh and Topology Plugins warn "mesh: false for HOST was written, but this Box's ssh config didn't follow (…): run roster sync" after a cut whose sync failed; the cut stands.

## v0.4.0

### New

**App**

- **A Plugin can read back what it added** (Plugin API 5, `roster.api_version` 5): every collection has `get`, `has` and `list`, as `init.lua`'s do: `roster.status.get("alerts")` gives a copy of the segment as the Plugin set it, `roster.sidebar.has("pinned")` says whether it has that section, `roster.views.list()` names its views, `roster.keymap.get("leader", "w w")` gives a binding's command line and `roster.details.list("reach")` the Hosts a section is on. See [What the Plugin added](plugin-api.md#errors).
- `init.lua`'s `roster.keymap.has(context, keys)` and `roster.themes.has(id)` say whether init.lua bound those keys and whether there's a Theme by that id, as every other collection's `has` does. See [`roster.keymap.has`](app/options.md#rosterkeymaphascontext-keys).
- **Badges are complete too:** `roster.badges.remove(host)` takes the Plugin's badge off a Host, and `get`, `has` and `list` read its badges back by Host. On Plugin API 5, taking off a badge it doesn't have (`remove`, or `set(host, nil)`) is an error at its line, as every other collection's removal is. See [`roster.badges`](plugin-api.md#rosterbadges).

### Changed

**App**

- A Plugin written for Plugin API 5 (`api = 5` in its manifest) gets an error at its line, as `init.lua` does, when it takes away what it never added: `roster.themes.remove` of a Theme it didn't define, `roster.keymap.del` of keys it didn't bind, any collection's `remove` (badges' too), and `roster.views.update`, `open` or `close` of a view it doesn't have. A key context other than `leader`, `list` or `list_vim` is an error there too, where the app refused it with a notice. A Plugin written for API 4 or older keeps the quiet removals. See [Errors](plugin-api.md#errors).

### Security

**App**

- **Prompt fill, tightened:** the fill key now types the Session's own Host's password only when the cursor is right after that very prompt, as a terminal draws it (Windows' redraws included), as a nested ssh's fill already needed; a sudo prompt that went by gets nothing and the vault isn't asked, and pressing the key again works once the prompt is back at the cursor. `terminal.read` Plugins no longer get any of a Session's shell-hook token when the output is split at an unlucky point or wraps it with links, colours or charset switches inside; ordinary output reaches them unchanged.

### Fixed

**App**

- **The fill key fills sudo with `pwfeedback`**: a sudo set to draw a `*` per key (`Defaults pwfeedback`) was refused as if its prompt echoed ("the prompt printed what roster typed to check it"). roster now takes sudo's `*` for its check, taken back, as no echo, read as the terminal draws it (Windows' redraws included), only at sudo's own prompt for the Session's own Host; the password goes in as `*`s, as when you type it, and `terminal.read` Plugins don't see those stars. Anything else printed still refuses, and so does a nested ssh's Host's sudo with `pwfeedback`. See [Filling a password prompt](app/security.md#filling-a-password-prompt).
- **A graph node you placed stays where you put it.** Dragged or moved with `m`, it no longer travels with its cluster when that cluster grows and moves out of its neighbours' way, and it doesn't count in the cluster's size, so a node dragged out over another cluster moves nothing. A graph whose clusters were saved overlapping by an older version is pulled apart the next time it opens. Graphs saved before this keep their places, but don't know which nodes you placed: one you dragged before may still move with its cluster once.
- **Zoomed out on a graph with many clusters, cluster titles no longer run over each other.** A title that can't be whole is cut to the room that's free, and one with no room at all gives way, as a node's label does, until you zoom in; the selected node's cluster always keeps its title.
- The Topology Plugin reads your Hosts without waiting for roster serve, so a big Inventory or a busy serve no longer holds up the Plugin (and `:topology`) while it's read. roster's own Plugins (mesh, topology, discover, and the recent-alerts and pinned examples) are written for Plugin API 5 now.
- **Ctrl+V pastes in a terminal on Windows**, as in Windows Terminal: the clipboard's text, through the terminal's paste (several lines as one bracketed paste), including from a voice-typing tool that pastes by sending Ctrl+V, and on any keyboard layout. With no text on the clipboard (an image, or nothing) Ctrl+V still reaches the program as ^V, so an app's own image paste and Vim's Ctrl+V work. Linux and macOS keep Ctrl+V for the program (paste with Ctrl+Shift+V there); `roster.keymap.set("terminal", "Ctrl+v", "terminal.pasteIfText")` pastes with it there too, and `false` gives it back on Windows. See [Copy and paste](app/keyboard.md#copy-and-paste).
- `roster.o.get("views")` reads any option by its dotted name, so a map with a key named `get`, `has`, `keys` or `reset` (where `:get()` and `:keys()` read that key) still has a read that always works.
- `:config import-terminal`'s preview names a `roster.o` line below the import block that sets the same option, at its line: running the import again replaces the block where it is, so that line still wins.
- Two examples in `:help options` that didn't load: `roster.o.List:insert` and `roster.o.List:clear`. Every documented `init.lua` example now loads in the tests, since lua-language-server lets through a value outside an option's set (`cursor_style = "triangle"`).
- Dropping a Host on a Folder no longer fails with ":folder can't run yet" when the app couldn't yet tell roster which commands are its own: the drop (and any Plugin action you start meanwhile) waits up to 5 s for that to get through, then runs. If it still hasn't, the drop is refused as before; try again in a moment. See [Errors](app/errors.md).
- On the docs website, a code block too wide for the page can be focused with Tab and scrolled with the arrow keys; a link whose text is a topic's name (`` [`mesh`](…) ``) is one link, no longer a link inside a link; and a screenshot in a guide shows as a link named after it in `:help` and on the website, where it was a stray "!" and a link with no name.
- A long option, command or error description shown beside its topic, in `:help`'s topic finder and on the docs website's search page, ends with "…" where it's cut at 80 characters, instead of stopping mid-word.
- A Plugin's view no longer goes back to an older state on a busy machine: when roster serve's answer to one of a Plugin's requests led it to ask again (the Mesh Plugin's job ending, then its status), the second answer's changes could reach the window first and be drawn over by the first's. The app now gets them in the order the Plugin made them. See [Asking roster serve](plugins.md#asking-roster-serve).
- **A Host you just added opens straight away:** every change the app makes to `roster.yml` (adding, editing, reviewing, renaming, moving or removing a Host, the group changes, Discover's add, "Save to vault", discarding the Pending changes, a pull) now runs `roster sync` for this Box, as Publish did, so its Session no longer fails with "isn't in this box's ssh config - run `roster sync`". An edit to `roster.yml` made outside the app syncs too once it's applied and loads. If the sync fails, the change stays and the message says so, with `roster sync` to run.
- [Shell integration](plugins.md#shell-integration) docs: a powerlevel10k recipe (its own `POWERLEVEL9K_TERM_SHELL_INTEGRATION` setting, since its instant and transient prompts can drop the snippet's marks), and where the shell-hook line stays in the history (PowerShell, zsh without `HIST_IGNORE_SPACE`, bash without `ignorespace`). The zsh, fish and PowerShell snippets and hook lines are now run in those shells in CI, as bash's were.

- `:plugins remove NAME` on a Package that `init.lua` still names is remembered, as a cancelled install is: the next start no longer asks to install it again while `init.lua` names it from the same repo and folder. `:packages` shows it as cancelled, and `:packages install NAME` brings it back. See [Packages](plugins.md#packages).
- `:check HOST` on a check that's already running (started elsewhere, or before the app restarted) shows the step it's on at once, instead of nothing until its next step starts. See [`:check`](app/errors.md).

**`roster serve` API**

- Each method that writes `roster.yml` (`host.add`, `host.update`, `host.review`, `host.remove`, `host.rename`, `host.move`, `group.*`, `discover.add`, `quick.save`, `host.save_login`, `changes.discard`, `inventory.pull`, `mesh.cut`'s `change`) runs `roster sync` after the write and says how it went in `sync: {ok, error?, fix?}`, as `changes.publish` does; so do `inventory.reload` and the `inventory.changed` notification when they apply a changed file that loads. A failed sync never undoes the change. No new API version: the field is new and optional. See [Editing](serve-api.md#editing-pending-changes).

- serve's log no longer says it "refused a token" when another serve starting up checks whether this one is still alive (it connects and hangs up without asking anything): it logs that a connection hung up without a request. A real unknown, used or expired token is still logged as refused, and no log line ever has the token in it.

### Deprecated

**App**

- A Plugin's removal of something it never added doing nothing: it still does for a Plugin whose manifest says `api = 4` or older. See [Deprecated names](deprecated.md).

## v0.3.0

### Breaking

**App**

- Plugin API 3 (`roster.api_version` 3): `roster.inventory.host(name)` gives `nil` for a name that isn't a Host, where it raised an error (code 2), so a Plugin that wrapped it in `pcall` checks for `nil` now. A `cmd:` or `env:` Login reference reaches a Plugin cut to its kind (`cmd:`, `env:`): it says how a secret is fetched, and a Plugin never needs it. See [`roster.inventory.host()`](plugin-api.md#rosterinventoryhostname) and [`LoginRef`](plugin-api.md#loginref).

### New

**App**

- **Neovim-style `init.lua`:** `roster.o.terminal.size = "16pt"` sets an option and `roster.o.terminal.size` reads it back (nil when unset), with nested objects needing no setup. A misspelled name is an error at its line in whichever module, with the name meant ("terminal.szie isn't an option (did you mean terminal.size?)"), and so is a value of the wrong type. Every option has the methods of its kind: a map's `m.KEY = nil`, `:has`, `:keys`, a list's `:append`, `:prepend`, `:insert`, `:remove`, `:has`, `:clear`, and `:get()`/`:reset()` on each, plus `roster.o.reset("terminal.size")`. Packages and Folders are added from any file with `roster.packages.add(…)` and `roster.folders.add(…)` (and removed, updated, read and listed: `remove`, `update`, `get`, `list`, `has`, and a Folder's `add_hosts`/`remove_hosts`); `roster.keymap` gains `del`, `get` and `list`, and `roster.themes` gains `update` (a bundled Theme too), `remove`, `get` and `list`. A second Package or Folder with the same name is an error naming both lines, and removing what isn't there is an error, never a no-op. New read-only fields: `roster.version` and `roster.config_dir`. Every write keeps its line, so `:options` names it even for a value set inside a table. `roster.set` and a returned table keep working. See [The `roster` table](app/config.md#the-roster-table) and `:help roster.o`.
- **An option reference, and `:options`:** `:help options` now has every `init.lua` option and every name of its `roster` table, one entry each, as Neovim's `:help 'option'` lists options: its type, its default, the values it can have (one of a few, a range, or a form), what it does and an example, with the value it has now and where that was set. Each is a topic: `:help terminal.size`, `:help keys.leader`, `:help roster.keymap.set`, `:help roster.config.Theme`. `:options` finds an option with its value now, where it was set (the file and line, the State, or default) and its default. `:config types` writes them as types for lua-language-server (`types/roster-config.lua` in the config folder), so your editor completes option names and shows the same descriptions. See [Option reference](app/options.md).
- **Fill sudo's password prompt from the vault:** when a Session waits at `[sudo] password for USER:` for its own login user, a note in the pane's corner offers `␣ p` (`:fill`), which types the Host's password from the vault: its own `sudo: {auth}` from `roster.yml`, else its ssh Login. Nothing is typed until you press it; the password goes from roster serve straight to the Session, never through the window or to a Plugin, and only once roster has checked the prompt doesn't echo and the Host hasn't changed since the Session connected. With shell integration it's offered only while the command running is sudo itself; without it the note says roster can't tell whether you're still on the Host. su's `Password:` is never filled. Needs roster serve API 25. See [Keyboard](app/keyboard.md) and [security.md](app/security.md#filling-a-password-prompt).
- **A nested ssh to an Inventory Host:** run `ssh esx-02` (or its address) inside a Session with roster's shell hooks on, and the Session's row and tab show where it is now, `esx-01 ─ esx-02`, until that ssh ends. When that ssh asks for esx-02's password, `␣ p` fills it from esx-02's own Login, and at the first command its marked shell runs, esx-02's sudo too. roster reads the ssh line with ssh's own rules and refuses anything it can't follow (`-J`, `-o ProxyCommand`, a wildcard, a Host it can't match by name, address and port); a key login types nothing; a host-key question stays yours, and once you've typed into the ssh it isn't filled. roster's hook marks now carry a per-Session token, so roster can tell its own shell's marks from the far Host's; with your shell's own integration instead, nothing nested is filled and every fill stops once something that may reach another machine has run (the note says how to fix it); without marks nothing nested is filled. Needs roster serve API 26 to fill (the breadcrumb needs 25). See [security.md](app/security.md#a-nested-ssh).
- **Your Plugins in `:tutor`'s demo:** the Plugins running in your workspace load in the demo too, with the permissions you granted them, so a Plugin's tutorial (`roster.tutor.set`) can teach the Plugin itself. There they see the demo's Hosts; roster serve answers only the demo's Host list, nothing reaches the network, and their files start empty and go when you leave. One that fails to load there doesn't stop the tutorial. See [A Plugin's tutorial](plugins.md#a-plugins-tutorial).
- `:plugins` shows how full each Plugin's data folder is against its limits: "Data: 2.1 MB in 34 files (of 10 MB, 1,000 files)", or "Data: none yet". It's counted when the panel opens, from the folder's listing alone. See [A Plugin's own files](plugins.md#a-plugins-own-files).
- **What a Plugin can read without waiting for an event** (Plugin API 4): `roster.sessions.list()` gives the Sessions open now, the ones that opened before the Plugin loaded too (with `inventory.read` or `terminal.read`); `roster.inventory.request(done)` reads every Host and group without waiting for roster serve; and `roster.inventory.hosts()` and `.groups()` in one call are one read of the Inventory, not two. A Plugin with `serve:host.check_job` can read how any check of a Host came out (the new [`CheckJob`](plugin-api.md#checkjob) type). topology shows the Sessions open before it loaded as live, and a Host whose check failed as down ("check failed at tcp"); it asks for `serve:host.check_job` for that, so updating it asks you once. See [`roster.sessions.list()`](plugin-api.md#rostersessionslist) and [Asking roster serve](plugins.md#asking-roster-serve).
- **Shell integration for Plugins:** if the shell on a Host prints OSC 133 marks (a few lines in its rc file; `:help shell-integration` has them for bash, zsh, fish and PowerShell), a Plugin with `terminal.read` hears `command_done` when each command ends, with its command line, its output and its exit code, and each run of `terminal_output` says what the marks call it (its new `kind`: `prompt`, `input` or `output`; a hint, since the Host prints the marks). roster only reads the marks: it never puts hooks on a Host or types into a Session. recent-alerts never alerts on a line the marks call a prompt or what you typed, and keeps its guess at your own echoed command for the rest. Plugin API 4 (`roster.api_version` 4). See [Shell integration](plugins.md#shell-integration).
- **Shell hooks, opt-in:** with `shell_hooks: true` on a Host in `roster.yml` (or `terminal.shell_hooks = true` in `init.lua`, or `:integrate` for the Session on screen), roster sends the shell one line after login that turns on its prompt marks (OSC 133) and its folder (OSC 7) for bash, zsh, fish and PowerShell, in that shell only: no rc file is touched. It's sent only at an empty prompt roster knows, before you type, and never to a menu, a forced command or a network CLI; the echo is kept off the screen. A Session's row shows the folder its shell is in. Off unless you turn it on. See [Shell hooks](plugins.md#shell-hooks-roster-sets-it-up).

- The Mesh gives a new `authorized_keys` it makes on ESXi (a user other than root) the sticky bit, so ESXi keeps it across a reboot.
- Moving a Host to another group keeps the `mesh_dir:` it inherited (roster writes it on the Host). Removing a source's `mesh_dir:`, or changing it, warns about the old directory until you delete it, and replaces the old `Include` in `~/.ssh/config`. See [`mesh_dir:`](mesh.md#esxi).
- A source that stops being one and loses (or changes) its `mesh_dir:` in the same edit is cleaned up from the directory it used until now, the one the `Include` in its `~/.ssh/config` names: an old `mesh_dir:` is warned about and kept (it was roster's default directory that went, with no word about the old one), roster's own default directory is removed, and the old `Include` goes. See [`mesh_dir:`](mesh.md#esxi).
- Publish's generated commit message names the `links:` that changed (`roster: add link orion-2 -> storage`), as it does Hosts and groups, rather than "roster: edit roster.yml".

### Security

**App**

- A Plugin can act on the network or the Inventory only when you've just asked it to: every serve method the install prompt flags (`mesh.apply`, `mesh.cut`, `host.check`, `discover.start`, `discover.add`, …) and `roster.inventory.update`, `.rename`, `.move` and `.review` work only in an action, command, finder item, toolbar control or question's answer of its own. At load, on an event or from a timer they're now errors (only `discover.start` and `discover.add` were held before). See [Plugins](plugins.md#asking-roster-serve).
- Only what you chose counts as your call: a finder's items as it opens, a `:check` section's lines and a question's cancel when another Plugin's question replaced it can no longer copy, ask, run a command line or call those methods, so another Plugin opening a finder can't lend them your call.
- `cmd:` and `env:` Login references are now cut from roster serve's error messages to a Plugin too, not only its answers.
- `roster.cmd` holds a command named after one of roster's (`open`, `check`, `plugins`, …) to roster's rule even if the Plugin added a command of that name.
- A Plugin can no longer keep your call alive by running its own commands through `roster.cmd` one after another: the command `roster.cmd` runs from your call is still your call (one hop, as a `roster.serve.request`'s answer is), but a `roster.cmd` or request made in it isn't, so the next command can't copy, ask, run a command line or act on the network. Folders' drag and drop still works. See [Plugins](plugins.md#asking-progress-the-toolbar-and-going-places).
- The `job_progress` event is cut as roster serve's answers are: a `cmd:` or `env:` Login reference in a job's text (a failed check's error message echoes the Login) reaches a Plugin as `cmd:` or `env:`. The cut reaches an answer's keys now too, not only its values.

**CLI**

- On Linux and macOS, `roster serve` removes its askpass folder (the private password socket's) however it ends: closed stdin even mid-request, SIGTERM, SIGHUP or SIGINT. A serve killed outright can't, so the next one to start removes this user's folders whose serve is gone, never another user's, a live one's or anything a link points at. Windows has no such sweep: the password pipe ends with serve whatever happens, and a folder a killed serve leaves under `%TEMP%` holds only Quick Connect's public host keys. On Windows serve also checks each askpass pipe client's process is yours, on top of the pipe's permissions.
- A Host check stopped while it logs in (`vault.lock`, `jobs.stop`) ends that login's ssh, so locking no longer waits up to ~35 s behind it.
- `--json` cuts `cmd:` and `env:` references everywhere in its output: in a key as much as a value, and in a value that isn't plain JSON (a set or a path), which went out uncut.

### Fixed

**CLI**

- A Mesh source moved back to roster's own directory (its `mesh_dir:` removed) that still holds the key from before the `mesh_dir:` gets a warning that roster uses that old key again, with `roster mesh --rotate HOST` to replace it; it was used again without a word. See [`mesh_dir:`](mesh.md#esxi).
- On native Windows, closing `roster serve` during a Mesh run ends the run's ssh with everything it started, as a step that times out does, so `mesh.json` records which Hosts were left to do (an ssh that is a batch file kept running before).
- The Mesh no longer writes a `via:` Link whose jump Host this Box has no host key for: the source's own Link to the jump Host isn't written then, so `ProxyJump` would have named a Host its ssh config doesn't have. Both are `no-host-key`, and `roster check` fails until `roster setup --only HOST` records the key.
- `roster discover --json` with a broken `roster.yml` found without `-c` (`ROSTER_CONFIG`, or the usual places) is error `1` with its fix, where it was ignored silently; with none at all it still scans.
- `roster serve` started with a temp dir whose path leaves a Unix socket's no room puts its askpass folder in `/tmp` rather than fail.
- `roster discover` scans IPv6 networks (nmap takes them only with `-6`, in a run of their own), scans an address that two of its networks hold once instead of writing it twice, and counts the hosts that answered with none of the ports open, as it said it did (nmap ran with `--open`, which leaves them out).

**App**

- `init.lua` runs as a block, as Lua runs a file: a one-line `require("me")` of a module that only makes `roster.*` calls loads, where it failed with "init.lua must return a table (it returned a boolean)" unless the file had a second line. `return require("me")` of a module that returns nothing says what happened and what to do. A bare `{ … }` with no `return` is now a syntax error at its line. See [How it works](app/config.md#how-it-works).
- Among `roster.*` calls the last one wins, so a module of overrides required after a base module takes effect (the first call won before). The returned table still wins over calls. See [The `roster` table](app/config.md#the-roster-table).
- A Config error in a value a required module returns names that module and line (`lua/opts.lua:4: …`), and one roster can't place says `(line unknown)`; it gave `init.lua` with a parent key's line, or the line of a `roster.set` whose value the returned table had replaced.
- A Plugin call that fails no longer leaves the buttons it was replacing dead ("that action is gone"), nor timers and commands behind it; 100 failed calls could use up a Plugin's timers.
- A Plugin that asks roster serve in a loop gets an error after 100 calls (or 300 s of waiting) in one go, instead of running for ever and keeping serve from the app.
- An answer to what a Plugin asked while loading is no longer lost (first load) or put on the load before (reload).
- A Plugin command whose line runs itself, or two that run each other, stop with a notice instead of recursing until the app gives up.
- A Plugin's `pairs` costs far less on a list (about 7 times faster on 10,000 items) and on tables with only text or only number keys, in the same order as before.
- The install prompt says what `serve:host.check` does: it connects to the Host and signs in once, changing nothing there or in the Inventory (it said it could change things on your Hosts). And a Plugin's command named after one of roster's (`:theme`, `:lock`, …) is never its own to run with `roster.cmd`, whichever of roster's it is, not only the ones that change trust or writes.
- Closing the app gives `roster serve` up to 3 s (was 1 s) to stop a running Mesh job and record what it didn't finish before it's killed.

**serve API**

- `host.check`: a waiting check that had joined another request's check answers `5` as soon as it's cancelled, rather than keep its worker until that check ends (up to 45 s); the check goes on for the others.
- `host.check` (API 22): a waiting check cancelled stops the check only when no other request waits for it and none asked for it in the background, where cancelling a request that had joined someone else's check stopped it for both; the background form says whether it `joined` a running check, and the app's core stops only a check it started when it gives up on it. A check asked for while the last one is stopping is a new check, not the stopping one (which answered `ok: false` with its steps skipped). `host.check_job` still finds a check that ended after a newer check of its Host started (it was `49`). A check shares the vault only for the steps that fetch a secret or mint a token, so an unlock or a lock no longer waits up to 45 s for a check (the lock screen hung, then failed).
- `vault.undo_create`: an undo that fails in an unexpected way keeps the item, so it can be undone again (it was forgotten: the item stayed in the vault and a retry answered `63`).
- `vault.configure` no longer fails ("dictionary changed size") when roster.yml reloads with a new provider while it runs.
- Closing `roster serve` mid Mesh job stops the job at once and records in `mesh.json` what it didn't finish (pending), where the job died with serve and the next run didn't know; a step cut short leaves each file whole.
- `discover.*`: IPv6 targets scan (with `-6`), a scan of IPv4 and IPv6 targets together no longer fails sorting them, an address two targets hold is visited once (`targets` drops the one another covers), `quiet` counts the Hosts that answered with none of the ports open (nmap; it's 0 with the built-in scanner, which can't tell them from no Host), and the built-in scanner reads its Hosts' SSH banners at once rather than one by one, so a batch (and a stop) no longer waits minutes.
- A background `mesh.plan` or `mesh.apply` works the Mesh out once rather than three times, two of them while serve answers nothing else.

### Deprecated

**App**

- `folders.yml`: Folders made in the app are kept by the Folders Plugin now. It's read once, to move its Folders in, and then no longer; hand-written Folders go in `init.lua`. See [Deprecated names](deprecated.md).
- `roster.keymap.set(context, keys, false)`: use `roster.keymap.del(context, keys)`. It takes the Plugin's own binding off now, rather than claiming the keys with no action. See [Deprecated names](deprecated.md).

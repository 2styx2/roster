# Spec 0001: roster v1 (Rust)

Status: **settled. The canonical spec is issue #3**, which adopts the proposed answer to every open question below. It also adds the plugin port: `roster NAME` runs `roster-NAME` from `PATH`, and the versioned `--json` output is the API. This file keeps the design rationale. Where the two disagree, the issue wins.

## Why

The owner's goal:

- open a terminal and reach any of 30+ Hosts in a keystroke or two;
- let Claude develop on them without ever seeing a secret;
- let the Hosts reach each other (the Mesh).

The Python roster grew to about 180k lines doing that and much more.

The owner's two rules:

> "A clean tool that is reliable and not bloated, with only the necessary stuff to get the work done for me and other people, plus features as long as they are useful."

> "I want this rewrite to be minimal with the only amount of loc you need to get the job done; more bloat, the less secure it becomes."

## Lineage: vis and dwm

roster follows the philosophy of [vis](https://github.com/martanne/vis) and [dwm](https://dwm.suckless.org/):

- **Do the core task and delegate the rest** (vis): "Vis strives to be *simple* and focuses on its core task." Its fuzzy file open dialog is "provided by independent utilities", and window management is delegated to "your terminal multiplexer". roster's core task is knowing the Inventory and getting you onto a Host safely. Picking is fzf's job, windows are tmux's, connections are ssh's, and secrets are the password manager's.
- **Clean over compatible** (vis): "The intention is *not* to be bug-for-bug compatible." roster-rs keeps compatible only what the switch-over needs.
- **Small enough to read in one sitting** (dwm): dwm stays under 2,000 lines, so anyone can audit it, and that's the security argument too. Extras are patches someone maintains, not features in the core.
- **Configuration is source, data is YAML** (dwm's `config.h`): the Inventory describes Hosts. roster's own knobs (worker count, picker keys, timeouts) are constants in `src/config.rs` (Q9).
- **The man page is the manual** (vis's `vis(1)`): `roster.1` is the reference, and `roster -h` prints usage only (Q10).

## Rules that shape every ticket

1. **Line ceiling: 10,000 lines of Rust**, counted as non-blank, non-comment lines in `src/`, the embedded sh scripts included and tests excluded. CI fails over the ceiling, and the owner can raise it in the PR that needs it. The ceiling is not a target: v1 is estimated at about 3,000 lines (see [Code layout](#code-layout-proposed)), and every PR states how many lines it adds.
2. **Crate allowlist** (enforced by `cargo deny`):
   - `lexopt` for argument parsing: a single file with no dependencies, instead of clap's derive stack. Help text is hand-written, which the "docs ship with the change" rule requires anyway;
   - `serde` and `serde_norway` for YAML, and `serde_json`;
   - `zeroize`.

   Everything else uses `std`: threads for parallelism, `std::os::unix::net` for askpass, and `std::process` for every tool. Adding a crate needs the owner's yes in the PR.
3. **Compose rather than reimplement:**
   - `ssh`, `ssh-keygen` and `ssh-keyscan` do all connecting and key work;
   - `fzf` picks;
   - `tmux` makes windows;
   - `curl` does HTTP;
   - `bw` (or any command, through `cmd:`) holds secrets.

   roster's own code is the glue between them, and knowledge of the Inventory.
4. **Secrets never reach stdout, logs, `--json`, Claude, argv, the environment, or disk.** The one exception is Bitwarden's session key file, kept for compatibility. A password goes from the vault to ssh through askpass, and to curl over stdin.
5. **Plain text by default, `--json` where a script or Claude reads the output** (`ls`, `run`, `check`). No colour.
6. **Idempotent and safe to interrupt.** Every file roster writes goes to a temp file and is renamed into place.
7. **Every flag earns its place.** When in doubt, leave it out. The user can always pipe the output into another tool.

## Vocabulary

From the Python roster's glossary:

- **Inventory**: `roster.yml`.
- **Host**: a machine or device in the Inventory.
- **Box**: the machine roster runs on.
- **Box key**: `~/.ssh/roster_<type>`, tagged `roster-managed:BOX`.
- **Enrolled Host**: one with the Box key installed.
- **Password Host**: `enroll: false`, always a password login.
- **Mesh**: Host-to-Host access.
- **Link**: one entry in `links:`.

## Commands

### v1

| Command | Job |
|---|---|
| `roster` | Picker: `roster ls` piped into fzf. Enter opens the Host in a new tmux window, `ctrl-v` in a split, and Tab marks several Hosts to open as synchronized panes. Outside tmux it execs `roster ssh` in place. |
| `roster ls [FILTER] [--json]` | One line per Host: `name  group  address  key\|password\|unreviewed  title`. FILTER matches the name, group, `type` or `product`. `--json` adds the resolved fields, never secrets. |
| `roster ssh HOST [ARGS…]` | For an enrolled Host, `exec ssh HOST ARGS`. For a Password Host, ssh runs with the password served by askpass. |
| `roster run TARGET [--json] -- CMD` | TARGET is a Host, a group, or a comma-separated list of them. Runs in parallel (`workers:`) and prints `host: line` per output line. Exit 1 if any Host failed. `--json` gives one object per Host: `{host, exit, stdout, stderr}`. |
| `roster check [TARGET] [--json]` | Per Host: does DNS resolve, does the TCP port answer, does `ssh -o BatchMode=yes HOST true` work (or, for a Password Host, does the vault reference resolve). On a failure, shows ssh's own error. Exit 1 on any failure. |
| `roster setup [--dry-run] [--undo]` | **Box side:** Box key, `~/.ssh/config.d/roster`, the `Include` line, `ROSTER.md`, and the Claude files. **Host side:** for each enrolled Host that doesn't yet take the key, install it (password from the vault) and record its host key; then apply the Mesh. `--dry-run` prints the plan. `--undo` removes everything roster put on the Hosts and the Box. |
| `roster vault unlock\|lock` | Bitwarden: unlock writes the session file, lock runs `bw lock` and deletes the file. |
| `roster web HOST [SERVICE] METHOD PATH [-d BODY]` | Runs `curl` with the service's URL and Login. The credential goes to curl as a config on stdin (`curl -K -`), never in argv. Basic and bearer only. |
| `contrib/tmux/roster.tmux` | About 10 lines: `prefix+r` opens the picker in a tmux popup. |

To add a Host, edit `roster.yml` and run `roster setup`.

### v1.1, each only if v1 leaves a real gap

- `roster watch [GROUP]`: a plain table redrawn every few seconds (up/down, load, RAM, disk, failed units) over the existing ControlMaster connections. No TUI crate.
- `roster scan CIDR`: wraps `nmap -sn` and prints the YAML of new Hosts, for the user to paste in with `reviewed: false`.
- Windows Hosts in `setup` (PowerShell key install). See Q4.

### Cut

These are deliberately not in the rewrite:

- the desktop app, `serve`, Lua and plugins, and named Inventories;
- `init`, `sync`, `discover`, `add`, `revoke` (it's `setup --undo`), `hosts` (it's `ls`), and `help --man`/completions;
- `vault reveal`, `vault status`, and the `bw`/`op` pass-throughs;
- the `op:`, `kp:` and template providers (`cmd:` covers them, see Q2), and Python provider plugins;
- `web` session logins (vsphere, unifi, openvpnas, hub) and output masking;
- Mesh `--rotate`, `cut HOST`, `leftovers`, `status` and drift detection;
- Box key rotation;
- `resources:`, `shell_hooks`, `sudo`, `mac`, `key_max_age` and `web_login_names`. These still parse, and are ignored.

## Compatibility with roster v0.7.0

**Only where both rosters touch the same thing.** Byte-identical output is not a goal. Whichever roster ran last writes its own valid version of a Box file.

| Shared thing | Contract |
|---|---|
| `roster.yml` | Every v0.7.0 Inventory loads. roster reads `groups`, `defaults`, `ip`, `user`, `port`, `auth`, `ssh:{user,port,auth}`, `enroll`, `reviewed`, `os`, `key_type`, `mesh`, `links`, `services` and `web`, plus `title`, `description`, `type` and `product`, and the top-level `box_name`, `key_path`, `key_type`, `workers` and `claude_inline_limit`. Any other key is accepted and ignored. The cascade is built-in < `defaults` < group < host, with `ssh:` beating the plain fields at each layer. |
| Inventory lookup | `-c PATH`, then `$ROSTER_CONFIG`, then `./roster.yml`, then `~/.config/roster/roster.yml`. |
| Box key | `~/.ssh/roster_<type>` (or `key_path`), made with `ssh-keygen -t … -N "" -C roster-managed:BOX`. On a Host it's the line `TYPE KEY roster-managed:BOX`. `--undo` removes exactly the lines with that tag. |
| ssh config | `~/.ssh/config.d/roster` (mode 0600), with first line `# Generated by roster from <path>`. `Include "<path>"` goes at the top of `~/.ssh/config`. Known hosts go in `~/.ssh/roster_known_hosts`. |
| Bitwarden session | `~/.config/roster/bw-session`, mode 0600, owned by the user, not a link. |
| `ROSTER.md` | Next to `roster.yml`, with v0.7.0's first line. The Host table is roster-rs's own. |
| Mesh on Hosts | The same key file names in `~/.ssh/roster-mesh/`, the same `Include` mark in `~/.ssh/config`, and the same peer line: `from="IP",no-agent-forwarding,no-X11-forwarding TYPE KEY roster-mesh:SRC@BOX`. |

## Vault

A secret is fetched only when it's needed, held in a `zeroize`d buffer, and never formatted.

| `auth:` | How roster resolves it |
|---|---|
| `bw:ITEM[#FIELD]` | `bw get item ITEM --nointeraction`, with `BW_SESSION` in the child's environment only. The field is the login password, the username, or a custom field. |
| `cmd:COMMAND` | Runs `sh -c COMMAND` and reads its first line of output. This covers 1Password (`cmd:op read op://…`), `pass`, KeePassXC and the rest. |
| `env:VAR` | Reads the environment variable. |
| `prompt` | Asks once on `/dev/tty`. |
| `agent`, `key`, `none` | No password. |
| anything else | Error: `auth "op:…" isn't supported; use cmd:`. |

## askpass (*proposed*)

The protocol is `std` only, with no token and no wire protocol.

1. roster gets the password from the vault.
2. It makes a 0700 directory under `$XDG_RUNTIME_DIR` (else `$TMPDIR`) and binds a Unix socket in it.
3. It starts `ssh` as a child with `SSH_ASKPASS=<roster binary>`, `SSH_ASKPASS_REQUIRE=force` and `ROSTER_ASKPASS=<socket path>`.
4. When ssh runs the binary as askpass, it connects, reads, and prints the password.
5. The parent accepts **one** connection, writes the password, then removes the directory.
6. The helper refuses any prompt that isn't a password prompt (host-key questions go to ssh's normal flow).

Only the same user can reach a socket in a 0700 directory, and a process running as that user could read roster's memory anyway.

## ssh

- **System OpenSSH**, not a Rust ssh library (*proposed*).
- **Batch work** (`run`, `check`, `setup`, Mesh) uses `-o BatchMode=yes` for enrolled Hosts, and askpass for Password Hosts.
- **The generated ssh config sets:** `HostName`, `User`, `Port`, `IdentityFile`, `IdentitiesOnly yes`, `UserKnownHostsFile`, `StrictHostKeyChecking accept-new`, and `ControlMaster auto`/`ControlPath`/`ControlPersist 10m`. A Password Host gets `PubkeyAuthentication no` instead of the key lines.
- **Windows Hosts:** `ssh` and `run` work as they are. `setup` skips them in v1 (Q4), and the Mesh skips them.

## Mesh (*proposed: minimal and stateless*)

**v1 scope:**

- `mesh: true` (cascading) makes a group's Hosts reach each other;
- `links: [{from, to, both}]` adds reach across groups;
- a Link with `via:`, a Host with `seen_as:` or `mesh_dir:`, and a Password peer are **skipped with a one-line reason**, so an Inventory that uses them still loads (Q3).

**How an apply runs:**

1. `setup` visits every enrolled, POSIX, reviewed Host, one at a time (because of rate limiters).
2. One sh script per Host reads what's there: its Mesh key's `.pub`, and the `roster-mesh:*@BOX` lines in `authorized_keys`.
3. A **pure planner** (Inventory + what was read → actions per Host) works out the changes.
4. A second sh script per Host applies them. It makes a key if there's none, writes the peers' known_hosts and ssh config, and adds or removes tagged lines, all written through a temp file and `mv`.

**No `mesh.json`.** A Host that's down stays as it was, and the next `setup` finishes it.

**Ownership:** roster adds and removes only lines tagged `@BOX`, and deletes only a key whose `.pub` carries that tag.

**`--undo`** removes this Box's tagged lines and Mesh files from every reachable Host, then the Box key lines, then the Box files.

## Testing and CI

- TDD, with one PR per ticket into `dev`.
- CI runs on Ubuntu:
  - `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test`;
  - `cargo deny check` (advisories plus the crate allowlist);
  - the line-budget check.
- **Fakes** are small sh scripts on `PATH` in `tests/fakes/`:
  - `ssh` runs the remote command with sh in `$FAKE_HOSTS/NAME`, and marker files make a Host down or Windows;
  - `bw`, `fzf` and `tmux` log their argv.
- **Tripwire:** a test fails if a real `bw` runs.
- **Fixtures are made up** (`box-a`, `esx-02`, `10.0.0.5`). Never output from a real Inventory.
- **One side-by-side test** (Q7): the Python v0.7.0's `revoke` and `mesh cut --all` recognise and remove what roster-rs wrote, and the other way round.

## Platform and install

- **Supported:** Linux, including WSL. macOS and native Windows aren't supported in v1.
- **Install: source only** (dwm style). No prebuilt binaries, packages or installer: build with `cargo build --release`, or `cargo install --git … --tag vX`. `Cargo.lock` is committed, and CI builds with `--locked`.
- **Requirements:** `ssh`, `ssh-keygen`, `ssh-keyscan`; `fzf` for the picker; `curl` for `web`; `tmux` is optional.
